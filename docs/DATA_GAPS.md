# Карта информационных пробелов

Назначение: превратить аналитическую работу в план развития каталога. Здесь зафиксировано, какие пользовательские сценарии мы уже можем закрыть текущими данными, а какие требуют нового сбора. Документ используется при планировании следующих этапов и при разговоре с заказчиком.

## 1. Что уже закрывается текущими данными

| Пользовательский сценарий | Что известно | Артефакт |
|---|---|---|
| Выбрать развитый курорт | OSM-инфраструктура в радиусе 6 км (трассы, подъёмники, размещение, питание) | `resort_features`, компонент «Инфраструктура» |
| Подобрать курорт по уровню катания | Разбивка трасс по сложности (`piste:difficulty`) и типам (`piste:type`) | `resort_features` (поля `piste_difficulty_*`, `piste_type_*`) |
| Понять, почему курорт высоко в рейтинге | 5 компонентных баллов и вклады | `resort_components`, `resort_reasons` |
| Сравнить 2–4 курорта | Баллы компонентов, сырые показатели, ограничения | `resort_scores`, `resort_components` |
| Понять, насколько устойчив рейтинг | Диапазон мест, частота топ-10, сценарии весов | `ranking_stability` |
| Выбрать сезон | Месячный климат (ноябрь–апрель) | `climate_monthly` |
| Оценить ближайшие дни | Прогноз 7 дней, состояние трассы | `weather_forecast` |
| Проверить достоверность данных | `confidence_score`, `quality_flags`, статусы координат | `resort_scores` |

Примечание: сложность трасс (`piste:difficulty`) — данные сообщества OSM, не официальная сертификация склонов. Тег проставлен на ~96% downhill-сегментов; у части курортов отсутствует (например, Холдоми и Гладенькая — 0 сегментов с тегом) — это видно по `piste_difficulty_coverage`.

## 2. Что мешает дать ответ (требует нового сбора)

| Пользовательский сценарий | Что уже известно | Что мешает | Возможный источник |
|---|---|---|---|
| Найти место для первых занятий | Разбивка трасс по сложности (`piste:difficulty`) | Учебные склоны и школы (инструкторы, зоны обучения) — сложность трасс их не заменяет | Сайты курортов, ski.ru |
| Выбрать поездку по бюджету | Ски-пасс для 9 курортов (сезон 2025/26) | Проживание, дорога, прокат, обучение; сопоставимые тарифы | API агрегатора (гипотеза — проверить), сайты курортов |
| Найти удобную логистику | Аэропорт и прямое расстояние | Время и стоимость трансфера, маршрут | 2ГИС/Яндекс, расписания |
| Поехать в ближайшие дни | Погодный прогноз | Открытые трассы и подъёмники, фактическая подготовка | Оперативные данные курортов |
| Оценить вместимость размещения | Количество объектов OSM | Вместимость, категория, цена | Сайты бронирования |

## 3. Чего в данных нет принципиально (межгодовые и структурные)

- Дни ниже −20°C — месячные средние не дают дневных экстремумов.
- Межгодовая изменчивость климата — данные усреднены за 5 сезонов.
- Энтропия/разнообразие по типам объектов — OSM-счётчики не имеют разбивки.
- Ценовая волатильность — 9 курортов и min/max по тарифам, не сопоставимый временной ряд.

## 4. Рекомендация по приоритету сбора

Не собирать всё сразу по 32 курортам. Разумнее полностью проработать 3–5 пилотных направлений (например, Шерегеш, Архыз, Кировск, Губаха, Игора) и проверить, достаточно ли такого набора для реального выбора пользователем. Если да — масштабировать; если нет — уточнить, каких полей не хватает.

## 5. Связь с дашбордом

Все незакрытые сценарии должны отображаться на дашборде как «неизвестно» (NULL), а не как ноль или «подходит». Для этого в витринах пропуски остаются `null`, а нейтральные баллы (например, `price_score = 50` без цены) не выдаются за реальные наблюдения — это видно по `has_observed_price` / `price_months_count`.
